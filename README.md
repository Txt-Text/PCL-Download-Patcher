# PCL Download Patcher

> PCL II 下载功能修补与恢复工具

鉴于最近的神秘事件，大部分大陆第三方启动器已无法进行原版游戏下载。

![](/Image/Reported-1.png "真的只是中国家长吗")

![](/Image/Reported-2.png)

但你可以使用本工具进行修补，修补后的 PCL 可以正常进行原版游戏下载、整合包下载、游戏修改、资源安装。

本工具为 C++ 开发的 Windows 控制台应用，完全免费开源。

## 修补与兼容范围

目前支持以下 PCL II 版本，包括正式版与快照版。社区版（PCL CE）暂不支持（但很快了...）：

- `2.99.0.0` ：五处下载功能。
- `2.99.0.1` ：上述五处，加上七处被隐藏的下载相关入口，共十二处。
- `2.99.0.0` 之前：检查已知功能，未发现下载拦截则不进行更改。
- `高于验证版本`：仅警告并检查已知功能，通过校验的结构仍进行修补。

程序先根据版本号选择检查规则，再通过特征扫描确认实际代码，而不是仅凭版本号、哈希或固定偏移判断或修补。

具体细节如下：

- 版本号从 EXE 的 .NET 程序集读取。
- 已恢复的功能将跳过，早于下载拦截引入版本仅警告，并继续校验以判断修补需求。
- 未识别/不支持的项将跳过，通过校验的功能仍可修补。
- 下载拦截按函数调用和指令结构识别，描述文字改写不会影响判断。

但如果后续 PCL 改了重要地方甚至删除了这些页面我也没办法，只能等待更新(甚至更激进的修补)，你可以发 Issue 提醒我啦...

程序会扫描以下功能，并显示识别结果与修补需求：

- 下载页面：恢复原版游戏版本列表的加载。
- 整合包下载：恢复本地整合包文件选择与后台安装，覆盖 CurseForge、HMCL、MultiMC、MCBBS、Modrinth、启动器打包和普通压缩包七类格式。
- Minecraft 修改页：恢复已有游戏的 Minecraft 选项显示。
- 资源安装入口：恢复整合包的点击安装和另存为，同时保留其他资源的保存行为。
- 下载相关入口（`2.99.0.1`）：下载页面导航、整合包搜索页安装按钮、禁用 Mod 页下载按钮、启动页下载引导、空版本列表下载按钮、Minecraft 更新提示中的下载按钮，以及版本选择页的整合包导入选项。恢复后仍尊重 PCL 原有的页面隐藏设置。

扫描过程中，某项功能因重命名、代码结构变化等原因无法确认时，会列出原因并跳过，不中断其他功能。生成补丁时发现不支持也会跳过该项，丢弃它已生成的修改。

PCL 编译时可能已删除被拦截功能的正常代码，因此只修改常量并不足以恢复下载。对于这类情况，修补器会利用目标文件中保留的功能重新生成所需的 .NET IL 代码。

修补器保留原有资源和方法，将恢复代码与更新后的 .NET 程序信息追加到可安全扩展的文件末尾区域；文件布局不支持时会停止修补。

开始修补后，程序将创建同目录 `.exe.pclfix.bak` 备份并校验 SHA-256。修改先写入临时文件，本次实际修改的功能全部通过检查、且原文件自扫描后未发生变化时，才会替换原文件。已有备份与当前文件一致时复用，内容不同时保留最初备份，并将修改前状态另存为 `.exe.pclfix.<SHA-256前16位>.bak`。

“还原 PCL” 仍还原最初的 `.pclfix.bak` 并校验哈希。修补直接修改 EXE 文件，会改变文件哈希；PCL 更新或重新下载后，可能需要再次修补。请保留备份文件。

扫描结果会分别显示需要修补、无需修补和已跳过的功能。存在跳过项时，完成提示会说明本次只修补了可确认的部分，不能保证全部下载功能均已恢复。没有可修补项时不写入文件；文件损坏、补丁修改冲突、写入失败或本次修改未通过验证时仍会停止操作。

## 开发说明

每个修补功能单独放在 `Features/` 的一个 `.hpp` 文件中，负责扫描（`Scan`）、生成修改（`Patch`）与验证（`Verify`）。程序启动时通过 `PatchRuleCatalog::BuiltIn()` 注册版本规则，再由 `Select()` 根据目标版本选择。每条 `PatchRuleSet` 集中保存编号、名称、说明、适用起点、已验证上限和修补功能集合，新增版本在规则表中登记即可，扫描和写入流程无需增加版本判断。修补方式变化时，可为新规则注册新的功能类；已有版本继续使用原来的类。

选择时使用起点不晚于目标版本的最近一套规则。早于首套规则时仍使用首套，超出已验证范围只警告，各个功能继续接受实际结构检查。新增功能可以沿用现有的备份、验证和文件替换流程。

- `TargetVersion.hpp`：四段程序集版本的比较与显示。
- `PatchRuleCatalog.hpp`：版本规则描述、功能组合的登记与选择。
- `Features/PatchFeatureRegistry.hpp`：持有一套规则的功能对象，按功能编号复检，不包含具体版本判断。
- `PatchTypes.hpp`：修补功能描述、扫描结果和修改计划。
- `ManagedPatch.h`：统一执行扫描、合并修改计划并生成待验证文件。
- `ManagedPatchContext.hpp`：读取 .NET 类型、函数和 IL 代码，生成修改后的 EXE。
- `ManagedRewrite.h`：生成 IL 指令并计算跳转位置。
- `ManagedResources.h`：读取目标程序内置的依赖文件。

## 编译

需要 Visual Studio、VS 的桌面 C++ 开发工具与 Windows SDK。项目语言标准为 C++20；Visual Studio / MSBuild 需要支持 `.slnx` 解决方案格式。

源码使用 UTF-8，编译时启用 `/utf-8`。控制台使用 UTF-8 代码页，直接输出窄字符串；重定向文件同样保存 UTF-8 文本。

```powershell
MSBuild PCL-Download-Patcher.slnx /p:Configuration=Release /p:Platform=x64 /m
```

生成位置：`build/bin/x64/Release/PCL-Download-Patcher.exe`。中间文件统一位于 `build/obj/平台/配置/`，最终程序位于 `build/bin/平台/配置/`。运行需要 Windows .NET Framework v4。构建 32 位版本时将命令中的 `x64` 改为 `x86`，输出位于 `build/bin/Win32/Release/`。
